# 방송 화면에서 선수 통계 읽기 (VOD GAME DATA)

공식 중계의 맵 종료 화면("GAME DATA")에서 선수별 E/A/D/피해/힐/경감을 읽는 방법. 영상 자체는 저장·배포하지 않고 숫자만 쓴다.

## 순서
1. `tools/vod_pipeline.py PART START END TAG` : 15초 간격으로 스캔 -> "GAME DATA" 제목을 이미지 비교로 탐지 -> 표/합계 화면 구분 -> 1080p 캡처
2. `tools/ocr_run.py OUT.json DIR...` : 숫자 글자 모양 비교로 표를 읽고, **팀 합계 화면의 합과 대조**해서 검증 (E, D, 피해, 힐, 경감)
3. `tools/ocr_names.py` : 선수 이름 글자 모양을 알려진 이름과 비교, 모르는 이름만 사람이 확인
4. 결과를 `data/manual/mapstats/YYYY-MM-DD.json` 에 저장 -> `node collector/build.mjs` 가 경기에 연결

## 데이터 형태 (`matches.json` 의 `mapStats`)
`m.mapStats = [{ game, map, mapTime, teams: { "팀명": [{ name, e, a, d, dmg, heal, mit }] }, reading, verified }]`
- E = Eliminations (어시스트 기여 포함), `reading` = manual | ocr, `verified` = 합계 화면과 일치 여부

## 라이브 자동 캡처 (OBS)
영상을 내려받지 않고, OBS 브라우저 소스로 SOOP 공식 임베드 플레이어(`/embed?autoPlay=true&mutePlay=true`)를 평소처럼 재생하면서(광고 포함, 화면에 표시 안 됨) 10초마다 그 이미지 1장만 받아 처리한다.

- `tools/live_capture.py` : OBS 실행 -> 10초마다 캡처 -> GAME DATA가 아닌 화면은 즉시 버림 -> 맵마다 표 3장 + 합계 1장 저장 -> `ocr_run.py` -> 끝나면 `assemble_day.py`
- `tools/assemble_day.py` : 이름 사전(`data/name_lib/`)으로 선수 이름, 선수 시트로 팀, 화면 머리글·밴 화면·Liquipedia 일정으로 경기/세트/맵 결정 -> `data/live/<날짜>/mapstats.json`
  (모르는 이름은 `name: null` + `unknownId: "?46"`(맵 4, 줄 6 = 맵 번호 × 10 + 줄), 크롭은 `data/live/<날짜>/unknown/`에 저장 -> 아래 "모르는 이름 붙이기")
  - 같은 날의 조립은 한 번에 하나(`data/live/<날짜>/.assemble.lock`), `mapstats.json`은 임시 파일에 쓰고 바꿔 넣음
  - 이름 사전이 비어 있으면 알림을 보내고 종료 코드 2로 멈춤. 굵은 숫자 사전에 0~9가 3개씩 없으면 하루 한 번 경고
- `tools/schedule_today.py` : 그날 한국 리그 첫 경기 10분 전에 `OWCSKR\LiveCapture` 작업 예약
- 바탕화면 `OWCSKR_예약등록.bat` : 매일 09:00 `OWCSKR\Daily` 작업 등록 (Liquipedia 갱신 -> 빌드 -> 당일 예약). 해제는 `OWCSKR_예약해제.bat`
- 사용자의 OBS 장면은 건드리지 않는다: 전용 장면 모음 `OWCSKR` 사용, 다른 장면 모음으로 OBS가 켜져 있으면 캡처하지 않고 종료

## 화면에서 직접 읽는 경기 정보 (Liquipedia 대기 없음)
- 경기 번호·세트 번호·맵 이름: 통계 화면 머리글("MATCH 2 GAME 3 / ESPERANÇA")을 글자 모양 사전(`data/header_lib/`, 로컬 전용)으로 읽음. 처음 보는 맵은 `?`로 두고 사전에 추가
  - 숫자마다 가장 가까운 글자와 두 번째로 가까운 다른 글자의 거리를 봄. 비율이 0.7을 넘으면 그 번호는 비움(`matchAmbiguous`)
- 머리글의 경기 번호는 다음이 모두 맞을 때만 씀 (10-23에 m04~m06 머리글이 1경기 그대로 남아 2경기 맵이 1경기로 들어간 일 때문)
  - 시간 순으로 경기 번호가 줄지 않음 / 그 경기 일정 시작 1시간 전보다 늦게 끝난 맵 / 그 경기가 일정에서 TBD가 아님 /
    맵 직전 밴 화면의 두 팀 = 그 경기 일정의 두 팀 / 알아본 선수의 팀이 그 두 팀 안에 있음
  - 머리글 경기 번호는 그날 중계의 경기 순번. 같은 날 한국 페이지가 둘이고 한쪽(오픈 예선·강등전)에 Liquipedia 중계 정보가 없으면
    중계 정보가 있는 페이지 경기만 셈 (시각 대체 경로도 같음). 지금 `data/lp`에는 그런 날이 없고, 오픈 예선·강등전은 중계 정보가 비어 있음
  - 다른 팀 선수로 읽힌 이름: 그런 이름이 하나뿐이고 다른 근거가 둘 이상(번호가 맞는 머리글, 밴 화면, 그 두 팀 선수)이면
    오독으로 보고 그 줄을 `name: null` + `misreadName`으로 바꿈(10-23 m09 `Soae`). 그런 이름이 둘 이상이거나 근거가 하나뿐이면
    (머리글만: 10-23 m04 낡은 머리글 + `Irony`) 그 경기로 정하지 않음
  - 밴 화면 두 팀이 그날 일정의 어느 경기도 아니면 잘못 읽은 것으로 보고 무시 (머리글을 막지 않음)
  - 하나라도 어긋나면 밴 화면 팀 -> 일정 시작 시각 순으로 경기를 정함. 밴 화면 팀이면 일정 순서와 달리 치른 경기도 받음.
    시작 시각은 Liquipedia에 시각이 없거나(00:00) 두 경기가 같은 시각이면 쓰지 않음. 시각으로 정한 경기는 "줄지 않음" 기준을 옮기지 않음
  - 플레이오프: 팀이 TBD인 경기는 `data/lp/*-korea.json`에서 가져와 일정에 넣고, 일정에 없는 두 팀의 밴 화면이 처음 나오면
    아직 안 채운 TBD 경기를 그 두 팀으로 채움 (그날 나머지 맵도 그 경기). 밴 화면 없이 TBD가 남으면 `labelVerified: false`
  - 세트 번호: 머리글(믿을 때) -> 밴 화면 점수(합 + 1, 각 0~3일 때만, 앞 세트 바로 다음일 때만 믿음) -> 머리글(경기 번호가 틀렸으면 바로 다음 세트일 때만) -> 맵 순서(안 믿음)
  - 맵 이름: 머리글을 믿으면 머리글 -> 밴 화면, 아니면 밴 화면 -> 머리글 (10-23 m05/m06 머리글은 1경기 맵 이름이었음). 다르면 `labelIssues`에 남김
  - 경기를 일정에 붙이면 맵과 `matches[]`에 `matchKey` = `"<competitionTitle>#<idx>"`(Liquipedia 페이지 제목과 순번,
    TBD 칸은 `data/lp` 페이지 제목). 같은 날 같은 두 팀의 재대결도 따로 남음. `match`(라벨)는 그대로
  - 같은 날 (경기, 세트)가 두 번 나오거나(추정 세트 번호는 세지 않음), 경기를 못 정하거나, 패널 팀을 알 수 없으면 `labelVerified: false`
  - 패널 팀: 알아본 선수의 로스터 팀 -> 없으면 밴 화면 순서(왼쪽 = 위 패널; 10-23 m01·m02·m04 이름으로 맞음, 더 확인 필요)
- 맵 시간: 팀 합계 화면의 "피해 ÷ 분당 피해", "힐 ÷ 분당 힐" (두 팀, 4개 값). 4개가 3초 넘게 어긋나면 시간을 비움 -> 10/11 12개 맵 전부 정확
- 경기 중 Liquipedia 요청 없음. 아침 일정(`data/site/matches.json`)은 경기 순서·두 팀·시작 시각 확인용
- 10/11 새 5개 맵을 화면 정보만으로 정리 -> 숫자·이름·경기·세트·맵·시간 정답과 전부 일치

## 밴 · 세트 승패 · POTM (중계 화면)
- 밴 화면(매 세트 전, 약 20초): 왼쪽 영웅 = 왼쪽 팀의 밴, 오른쪽 = 오른쪽 팀. 영웅 아래 `INITIAL BAN`/`FOLLOW-UP BAN`으로 선밴/후밴. 가운데 `SELECTED MAP`, 위쪽 바에 팀 이름과 **그 세트 전 세트 점수**
  -> 세트 승자 = 다음 밴 화면에서 점수가 오른 팀(1세트는 밴 화면을 못 읽어도 0:0), 마지막 세트 = 앞선 팀(동점이면 POTM 팀)이
     그 세트로 시리즈를 이길 때만 (BO5 2:x, BO7 3:x. 형식을 모르면 3:x만). 다음 세트를 못 잡았을 때 앞선 팀에 승리를 주지 않기 위해
  - 점수가 0~3이 아니면(애니메이션 중 판독 `130-80` 등) `seriesBefore`를 남기지 않음
- POTM 화면(경기 직후, 약 15초): 이름 + 경기 전체 ELIMS/DEATH/E/D/DMG/DMG/M
  - 숫자는 ELIMS·DEATH·E/D가 모두 읽혔고 ELIMS > 0, `|ELIMS/DEATH - E/D| < 0.06`인 장면 중 ELIMS가 가장 큰 장면에서 가져옴 (등장 애니메이션 장면 제외). 없으면 비움
  - 이름은 그 경기 두 팀 로스터(`players.json`, `0/o 1/l/i 3/e 5/s` 같은 글자와 `handle-aliases.json` 반영)에 있을 때만 받음. 팀도 로스터에서 찾음.
    이름을 못 읽었으면 표에서 경기 전체 킬·데스가 하나만 같은 (이름을 아는) 선수. 둘 다 안 되면 `potm: null`, `potmMethod: "unresolved"`
  - POTM 카드는 그 경기 마지막 맵 뒤, 다음 경기 첫 맵 앞(30분 안)의 것만, 한 카드는 한 경기에만 씀
- 판독: 이름·영웅·맵·팀 = Tesseract OCR + 알려진 단어 목록으로 보정, 점수·POTM 숫자 = 굵은 숫자 사전(`data/digit_lib/`, 로컬)
  - 밴·POTM 화면 찾기(`ocr_screens.screen_kind`): `SELECTED MAP`/`PLAYER OF THE MATCH` 글자를 기준 그림과 비교. 그래픽이 몇 픽셀
    밀려도 놓치지 않도록 ±12 px(960 기준) 안에서 가장 잘 맞는 자리를 찾음(`screen_match.locate`). 문턱(0.8/0.85)과 제자리 점수는 예전과 같음.
    판독 칸은 아직 제자리 기준이라, 많이 밀린 화면은 찾기만 하고 팀·맵을 못 읽을 수 있음(그러면 그 밴 화면은 무시됨)
  - 판독 결과는 프레임마다 `data/live/<날짜>/screens_cache.json`에 남김(파일 이름 + 크기 + 수정 시각). 조립할 때마다 새 화면만 읽음.
    코드 판(`SCREENS_CACHE_VERSION`), 단어 목록(`matches.json`·별칭), 숫자 사전이 바뀌면 전부 다시 읽음. 깨진 파일은 무시하고 다시 만듦
  - 글자마다 사전과의 거리가 컷을 넘으면 사전 판독을 버리고 Tesseract로 읽음. 컷 = 같은 숫자 샘플끼리의 최근접 거리 95번째 백분위수 × 2
    (다른 숫자와의 거리 중앙값의 절반보다 작게는 안 함). `OWCSKR_DIGIT_CUTOFF`로 바꿀 수 있음
  - 처음 만든 사전에는 6이 없음. 샘플 추가 방법은 `tools/build_digit_lib.py` 머리말
